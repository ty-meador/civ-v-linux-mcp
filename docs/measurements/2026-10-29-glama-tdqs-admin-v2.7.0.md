## turn  A 3.6/5
A dense but information-rich definition that clearly enumerates the five turn operations, their boundaries, and the blocking/timeout return semantics. Its weaknesses are a wall-of-text structure and no differentiation from sibling tools, plus reliance on the schema for most parameter detail.

The description adds genuinely useful semantics beyond that: blocking behavior, the default 600s timeout, and the reassurance that a timeout returns 'with my_turn false, nothing lost'. The lack of per-action structure makes it harder to parse than its length warrants.
- Completeness 4/5: For an 8-parameter tool with no output schema, the description does explain the return shape ('turn, my_turn, `gate`... todo / decisions, digest, notes') and the timeout return case. Given annotations cover the safety hints and the schema covers every parameter, this is close to complete; only cross-tool routing and failure/permission behavior are absent.
- Parameters 3/5: Schema coverage is 100%, so the baseline is 3 and the schema already documents all eight parameters, including the per-action applicability of `notes`, `since`, `detail`, and `limit`. The description adds marginal clarity on `args` (skip_quiet_turns, wake_on, autosave, briefing) and that `actions` rows are 'as the reads hand them back', but it is largely restating the schema rather than deepening it.
- Purpose 4/5: The description enumerates five concrete operations (status, briefing, finish, end, wait) and states what each one does, e.g. 'finish (run `actions` rows, end the turn, wait until it is mine again)'. It's a specific resource (the turn clock) with a clear action taxonomy, but it doesn't explicitly distinguish itself from any of the sibling tools (state, question, batch), leaving that inference to the agent.
- Usage Guidelines 4/5: It draws the key boundaries among its own actions: 'end (end the turn only)' vs 'finish (run `actions` rows, end the turn, wait until it is mine again)', and 'wait (block until it is my turn)'. It also gives contextual triggers such as "since='turn' after a context reset" and "detail='digest' for the event digest alone". What's missing is any guidance about when to reach for a sibling tool instead.
